# MINDPRINT Simulation Architecture

## Purpose

The simulation layer is a research architecture above the existing production
assessment and 12-task Experimental Battery. It does not modify either scoring
system.

## Observation vocabulary

The simulation platform uses five levels:

### Environment

A reusable dynamic paradigm such as Dynamic Attention Field.

### Trial

One decision/prediction unit inside an environment.

### Event

A change generated by the environment: signal update, evidence arrival,
interruption, feedback, rule change, or decision checkpoint.

### Trace

A structured behavioral record created by a user action or environment/user
interaction.

### Observation

A research interpretation derived from one or more traces in context.

Example:

Environment: Dynamic Evidence Stream  
Trial: one evidence checkpoint  
Event: new independent trial arrives  
Trace: confidence changes  
Observation: confidence adjustment relative to evidential strength

A trace is not automatically a construct score.

## Engine boundaries

The domain layer lives under src/assessment/simulations/.

- types.ts: canonical simulation and trace types
- model.ts: research construct ontology
- environments.ts: eight environment-family metadata records
- timeline.ts: deterministic event ordering and step/real-time capability
- traces.ts: trace schema and construct-hypothesis mapping
- adaptive.ts: deterministic adaptive-difficulty rules
- prototypes.ts: three English-first prototype definitions
- session.ts: isolated local simulation session
- diagnostics.ts: internal research summaries
- engine.ts: guardrails and shared engine helpers

React components render the domain definitions but do not own answer rules or
construct metadata.

## Environment families

1. Dynamic Attention Field
2. Hidden-System Learning
3. Dynamic Evidence Stream
4. Information Search Environment
5. Structural Transfer Environment
6. Adaptive Rule / Volatility Environment
7. AI Collaboration Environment
8. Uncertainty & Decision Environment

The first three have runnable prototypes in Milestone 14. The other five are
research family definitions, not unfinished user questions.

## Timeline modes

The architecture recognizes:

- step mode;
- real-time mode.

Milestone 14 prototypes intentionally use step mode. This reduces device timing
dependence and provides an accessible path through the same event structure.

Future real-time variants must preserve a step or controlled-pause alternative
when doing so does not invalidate the research question.

## Prototype 1 — Dynamic Attention Field

Eight simultaneous signals change across four frames. Two signals are
diagnostically relevant. A visually salient social-mention spike acts as a
distractor and explicit interruption.

Recorded traces include signal-selection sequence, interruption recovery,
final selection, and confidence.

These are interaction-based proxies and are not gaze data.

## Prototype 2 — Hidden-System Learning

Participants make repeated numeric predictions and receive outcome feedback.
An initial mapping changes once without an announcement, followed by a transfer
probe.

Recorded traces include prediction sequence, errors, first successful
post-change detection, and final transfer prediction.

No artificial waiting delay is used.

## Prototype 3 — Dynamic Evidence Stream

Four evidence events arrive sequentially with different evidential strengths
and directions. One strong independent randomized trial contradicts earlier
positive evidence.

Participants commit a judgment and confidence after every event. Correctness
feedback is not shown during the stream.

Recorded traces include belief trajectory, confidence trajectory, revisions,
and final judgment.

## Session isolation

Simulation research state uses its own localStorage key:

dynamic-simulation-research-session

It does not share production or Experimental Battery session state.

## Accessibility and motion

The current prototypes are keyboard-operable, display underlying numeric/text
information, and use semantic controls.

The application already respects prefers-reduced-motion globally. Signal-bar
transitions therefore collapse under reduced-motion preferences.

Step mode is the default research mode. Animation is never the sole carrier of
meaning.

## Device and browser limitations

Consumer browsers are not laboratory reaction-time equipment. Timing is
contextual process data.

Dynamic attention and dense visual environments may have meaningful mobile vs
desktop effects. Device sensitivity is recorded as research metadata, not used
to alter production scores.
